# 在画布和左侧树中删除节点

状态：此前基线提交为 2572666。当前行为以下一节为准；后文保留早期设计和验证记录，其中“删除节点保留可见会话”等行为已被最新选择替代。

## 当前规则（2026-11-01 最新选择）

- 一个节点绑定一个普通 DSH Session（当前绑定），同时按 Session ID 独立保存历史来源记录（`session-links.json`），不被新建会话覆盖。
- 删除节点及子树：节点及子树进入 Atlas 回收站，保留绑定记录；移除对应 DSH 工作区分组，Session 进入 DSH「未分组」，**不归档**，仍可独立使用。运行中拒绝删除。恢复节点恢复原树关系、位置和内容，继续绑定原 Session、恢复对应工作区分组。
- 归档会话（右键「归档会话」/会话页「归档」）：节点保留，调用 DSH 原生归档，成功后清空节点当前绑定并保留历史来源记录。归档状态以 DSH 原生归档为准，Atlas 时间戳仅作展示。
- 恢复归档会话（会话页「恢复会话」）：按 Session ID 操作，先取消 DSH 原生归档；来源节点存在、未删除且当前无会话时自动回绑，否则只恢复该 Session 的可用性、不覆盖当前绑定、不重建节点。
- 彻底删除节点：永久删除 Atlas 节点记录与对应工作区分组，保留 Session、历史日志与工作目录（cwd），不改变 Session 归档状态。之后恢复会话也不重建已删除节点。
- 原生删除 DSH 工作区分组：不删除 Atlas 节点，不把节点/子树移入回收站。分组缺失仅作显示状态或显式修复依据，读取快照/后台轮询不触发节点删除。

验证：`npm run check`（typecheck + build + smoke + session-routing + node-trash）。smoke 覆盖删除不归档、恢复回绑、归档/恢复、S1→S2→恢复S1 不覆盖 S2、彻底删除后恢复不重建节点；session-routing 覆盖原生分组删除不改变逻辑树。未对真实用户数据执行删除，未调用真实模型。

## 当前问题

- 画布 `src/client/Canvas.tsx` 只有打开、拖动、创建子节点，没有右键菜单。
- 左树 `src/client/SessionTree.tsx` 的右键目前只展示创建子节点。
- 旧 ChatSheet 有删除按钮，但现在已绑定 Session 的历史视图为只读，所以不能作为新的删除入口。
- 现有 `AtlasStore.deleteNode`（src/host/store.ts）会递归硬删节点、旧线程消息和卡片；不删除 DSH Session 或工作目录。不能直接把这一操作接成无提示的右键菜单。

## 推荐行为

画布卡片和左侧节点行共享右键菜单：打开会话、创建子节点、删除节点…。菜单按视口边缘调整位置，点外部或 Esc 关闭；右键不触发节点跳转或拖动。增加键盘菜单入口以支持不方便右键的操作。

“删除节点…”进入内嵌确认对话框，不使用 window.confirm。叶子节点展示节点名称；包含后代的节点展示“本节点及 N 个子节点”及受影响列表，防止把收起的后代漏掉。确认按钮写明“移至回收站”。第一版不提供自动提升子节点或同时销毁 Session 的组合选项。

删除以 Atlas 回收站为主，保留节点、原 parentId、位置、旧 Thread/消息/引用/卡片、Session 绑定。DSH Session、DSH Workspace 注册和磁盘工作目录均保留，不自动终止正在运行的 Agent。若受影响节点仍有运行任务，先阻止操作并说明任务仍在运行，让用户通过原生界面停止后重试；具体运行状态检查须接真实 DSH 状态。删除逻辑不是工具执行权限撤销。

## 最小实现

1. 节点增加可选 deletedAt 和 deletionBatchId。一个删除批次包含目标及全部后代，在单次节点文件写入中标记；旧数据缺省视为正常。不删除其他文件。新增按批次恢复操作和简单回收站入口，恢复原关系前检查父节点是否仍存在/仍被删除。
2. Store 查询区分可见节点和全部节点。画布、树、搜索、Session 打开、创建子节点等普通入口排除已删除节点；Session 绑定唯一性继续检查全部节点，避免回收站中的 Session 被重复绑定。复核原有 ChatSheet 的删除接口，使其同样经过安全语义。
3. 删除请求带预览所依据的 revision，服务端重新计算后代和检查运行状态；预览之后新增子节点或其他并发修改时返回冲突，刷新确认范围，不能按陈旧列表删除。重复删除/恢复不重复产生副作用。服务器返回实际处理的 ID 列表。
4. 当前节点被删除后切到仍存在的父节点；没有父节点则回画布。清理失效的前端选择；画布、树、搜索同步刷新。提供撤销/回收站恢复入口，恢复后 Session 仍可打开。

## 验收

- 右键不打开 Session；菜单不会越出屏幕，Esc/外部点击关闭。
- 叶子、收起的子树、根节点均展示正确删除范围；取消不改数据。
- 节点消失但旧消息、卡片、绑定、DSH 日志与目录保留；恢复后能重新打开原 Session。
- 删除当前节点、重复点击、多个标签页并发、确认期间新增子节点、正在运行的任务均有确定结果。
- 用临时目录及复制数据测试；用户真实节点不作为测试对象。业务测试与 DSH 状态/浏览器验证分别记录。

## 需要对齐的一个选择

推荐“删除节点及子树 → 回收站，可恢复，保留 DSH Session”。若用户要的是“永久删除并连带销毁会话/文件”，需要另立操作和明确范围，不与本菜单默认动作合并。

## 用户确认与新增约束

已确认：删除 Atlas 节点后，保留对应 DSH Session 和文件；需要 Atlas 回收站，并希望会话收纳到原生默认工作区。

源码核对发现：DSH rc.2 的 `WorkspaceEntity.attachSession`（packages/workspace/workspace/src/entity.ts:110）会校验 Session Header 中 cwd 的规范化路径必须与 Workspace.path 完全一致，否则拒绝附加；该类型契约见 types.ts:103。当前 Atlas 按节点创建独立目录和 Workspace，因此不能直接把既有 Session attach 到不同路径的默认工作区。detach 不删除日志，但也不能解决默认工作区的路径校验。修改运行时 working_directory 不能当作修改不可变来源 cwd 的替代方案，不能私改 Session Header/JSONL。

待确定的实现方式：如果目标仅为统一显示，可以新增 Atlas 管理的“保留会话”收纳视图，不改变真实 cwd/权限，不将其假称原生默认工作区绑定。若必须显示在 DSH 原生“默认工作区”下，需要评估将会话展示分组与执行目录分离的最小宿主/UI 扩展，给出可复现探针后再决定补丁/Fork。未验证前不承诺原生跨目录移动。

回收站记录原绑定及原 Workspace 归属和转移状态；跨 Atlas 与 DSH 的操作需要可恢复状态与幂等重试。只有确认收纳成功才报告迁移完成。恢复节点时继续使用原 Session；其间新增消息和文件保持现状，不回滚或复制 Session 历史。

## 本轮实现与验证

画布与侧栏共享 NodeActions 右键菜单及删除确认框，提供 Shift+F10/菜单键入口。AtlasStore 软删除在同一 nodes.json 中标记 deletedAt/deletionBatchId/deletionRootId，保留其他文件。删除预览 token 使用完整节点集合摘要，任何期间的节点变更都会使确认失效；同批次重复删除幂等。工作区快照、搜索及旧线程入口排除回收站节点，唯一 Session 绑定检查仍覆盖回收站。新建节点保留原有墓碑记录。

回收站按批次恢复；原父节点仍在其他删除批次时提示先恢复父节点。“保留会话”收纳所有回收站节点中绑定的 Session，打开原生聊天，不改原生 Workspace 绑定、工作目录、消息或文件。恢复不回滚其间对话与文件。当前节点删除后回到仍存在的父节点，否则回画布。通过页面内变更事件更新画布/侧树；其他浏览器标签页需刷新，但后端对陈旧删除预览仍检查冲突。没有清空回收站/永久删除入口。

测试：npm run check 包含旧回归、HTTP 运行中删除拒绝/保留会话/恢复、tests/node-trash.mjs 的子树、陈旧 token、独立删除批次、重复请求、Store 重建、绑定及消息/卡片/文件保留。npm run test:dsh 为真实 DSH 组件配模拟模型运行，不等于真实模型或 OS 安全。

浏览器：隔离 DSH rc.2 Web profile 实测画布右键删除两节点子树，保留会话可打开原 Session 并显示原历史，回收站恢复原树；侧树右键不触发跳转，删除当前子节点后切到父 Session。截图 assets/retained-sessions.png、assets/node-recycle-bin.png。用户真实数据未用于删除测试。

运行状态检查只拒绝检查时已经运行或正在打开的会话，不撤销 Session 执行权限，也不保证阻止从其他原生入口在检查后启动。当前节点存储仍是单 Host 实例下的队列和原子文件替换，不宣称多个独立 Host 进程同时写同一 Atlas 目录安全。
