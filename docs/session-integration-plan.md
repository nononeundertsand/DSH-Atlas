# 将 Atlas 节点接入 DSH Session

状态：已实现节点跳转和原生左树/右侧聊天，并完成隔离 Web 浏览器验证；结果及未验证边界见 [实现与验证](session-integration-results.md)。分支：`codex/dsh-session-integration`。基准：Atlas `e41b5d7`，DSH `0.2.1-rc.2`，源码与现状见 [第一轮审查](session-tree-assessment.md)。

## 目标与验收

以一个 Atlas 节点完成真实 DSH 运行时的纵向闭环：

1. 创建节点并唯一绑定一个普通 DSH Session，保存映射。
2. 从节点发送消息，进入该 Session 的 DSH Agent 和工具循环；用 Session 日志及模型 fixture 请求证明，Atlas 自己的 `llm.stream` 主聊天链路没有被调用。
3. 同一个受控工具在临时授权目录内成功、在授权目录外拒绝，检查工具结果与实际文件内容。
4. 释放 Agent 后按同一 Session ID 恢复，再次发送并确认历史和新事件。
5. 从 Atlas 打开 DSH 原生 Conversation，看到同一 Session 的消息与工具调用记录。

五项必须分别提供测试与运行证据；真实 DSH 加模拟模型不等于真实模型。工具边界测试通过不等于通用 OS 沙箱、多工具或跨平台安全。

## 边界与约束

- 使用普通 Session；Atlas 的逻辑父子与 DSH `parentAgent`、Subagent 及 Fork 来源分离。不修改 DSH Agent Loop，不直接改写 Session Header/JSONL。
- 以 Atlas 树为主要入口并复用原生聊天；先做单节点导航验证，保留画布和现有 ChatSheet。现有视图继续可用，具体呈现以实际扩展点为准。
- 保留旧节点、Thread、消息、引用、卡片和位置。第一闭环只用新建的隔离测试数据；真实数据迁移、批量修改、删除或覆盖另行讨论。
- 新建子任务默认仅提供用户确认的任务说明和所选材料；本闭环先验证单节点，不默认复制父历史或把成果自动注入其他节点。
- 所有测试使用隔离的临时 profile、工作区和 DSH 数据目录；启动前确认 DSH 的 home 与配置解析实际指向临时位置，禁用真实凭据及外部网络，不修改用户 `~/.dsh`。真实模型调用的费用需提前明确，不作为模拟模型测试的隐含结果。
- 保留已有未提交文件，不执行破坏性 Git 操作。文件上传、通用多层树、正式迁移、跨平台隔离不视为此五项已经完成的能力。

## 阶段 0：建立可重复的真实 DSH fixture

**工作**：检查 rc.2 官方包或源码的启动与测试方式，准备临时 profile、存储根、固定响应模型和受控工具。明确 mock 的边界：模型可模拟，Session、Agent Loop、工具调度和持久化必须由真实 DSH 组件承担。测试前审查 fixture 的配置和清理脚本，确认不会读取凭据、请求外网或写入真实目录。

**验证**：启动并关闭 fixture，记录 DSH 版本、解析后的 profile/数据路径及监听地址；证明隔离目录以外无测试写入，测试完成后仅清理测试自己创建的目录。不能确认隔离时停止该运行，不使用真实 profile 代替。

## 阶段 1：创建节点与绑定 Session

**候选改动**：`src/shared/types.ts` 增加兼容旧数据的绑定表示；`src/host/store.ts` 持久保存和查询映射；新增小型 DSH Session 适配边界，由 Host 长寿命作用域创建普通 Session。先核对是否可复用 DSH Session controller 的 preset、workspace 与恢复流程，不自行伪造 Session 元数据。

**验证**：通过真实 fixture 创建节点和 Session，核对 ID、普通 Session 来源、DSH 日志及节点快照；重复绑定、部分创建失败和再次打开应能发现并处理不一致，不能静默创建重复 Session。旧节点及其文件读取保持兼容。选择具体的失败恢复/幂等机制后再实现，不预设多文件写入是事务。

## 阶段 2：发送消息与工具调用

**候选改动**：增加针对已绑定 Session 的发送路径；主聊天走 DSH Session/Agent，Atlas-native 旧线程继续作为历史路径。记录并验证消息进入 Session 的事件序列；真实 DSH Agent Loop 执行工具后继续输出。

**受控工具**：先选一个可确定输入和副作用的文件工具，在隔离根目录内允许写入，在另一个临时目录内拒绝；在 DSH 工具执行入口应用策略并核对日志与磁盘。测试拒绝必须确认目标内容未改变，不能只断言返回了一段错误文本。检查直接通过原生 Session 入口发送时策略仍生效；恢复时策略重新应用。

**验证**：fixture 模型有意发出工具调用并消费结果；断言有 `tool/call`、`tool/result`、后续模型步骤和可定位的用户消息。独立探针确认 Atlas 主聊天 `llm.stream` 没有被调用。覆盖工具拒绝、失败、取消与重复请求；不依赖真实模型是否主动选中工具。

**权限限制**：先清晰列出实际保护的工具、路径及入口。`tools.restrict`、`tools.guard` 或文件 intent 的作用范围以真实 DSH 验证为准；不得宣称插件卸载后或通过其他工具、shell、MCP、网络等入口仍有隔离。无法强制恢复或入口切换时，不宣布安全闭环完成，记录缺口和最小上游补丁候选。

## 阶段 3：释放与恢复

**工作**：以受控方式释放 Agent handle；保留持久 Session，恢复时沿 DSH 的正常组合路径重新应用 preset 和策略，保持 Host scope 所有权与逻辑树解耦。

**验证**：释放前后均使用同一 Session ID；恢复前后检查日志与请求历史，发送新消息并获得回应；模拟恢复失败和重复恢复。另做一次隔离 Host 重启后的恢复验证，单独记录结果；重启成功不能由单纯释放/恢复推断。

## 阶段 4：原生聊天展示

**候选改动**：Atlas 节点提供打开已绑定 Session 的动作，优先研究 DSH 的 `uiWorkspace.openSession` 与 `conversation` 主面板，不先重做工具卡。单节点验证可先复用现有节点入口；树作为主要导航的完整布局在此基础上验证，避免引入两套重复导航。原有画布和 ChatSheet 不删除。

**浏览器验收**：在隔离 fixture 中，从 Atlas 点开节点，确认原生 Conversation 绑定的是同一 Session，显示用户消息、助手回复、工具调用与结果；切换节点和刷新后仍能回到正确 Session。验证入口保留原生审批组件的条件；如果权限流程有实际审批，再单独验证审批显示与决策，不把工具卡通过等同于审批已验证。截图与日志不含个人资料和真实凭据。

若 slot/导航扩展不足，保存最小复现和源码位置，先比较插件方案与最小上游补丁，不直接改 DSH 或默认 Fork。

## 测试分层与交付记录

| 层次 | 验证内容 | 结论边界 |
|---|---|---|
| 业务逻辑 | 节点映射唯一、旧数据可读、创建失败与重试、重复绑定 | 不证明真实 DSH 集成 |
| 真实 DSH fixture | Session 创建、Agent Loop、受控工具 allow/deny、释放和恢复、Session 事件 | 模型可模拟；不证明真实模型或通用 OS 安全 |
| 浏览器 | Atlas 入口、原生 Conversation 同一 Session、工具展示、刷新 | 不证明所有插件版本兼容 |
| 真实模型 | 仅在明确费用和网络条件后，可选验证模型自然选择工具 | 不替代拒绝与安全测试 |
| OS 安全 | 另列目标系统及工具，测试路径穿越、symlink、子进程等 | 单次文件工具拒绝不证明全面隔离 |

每个阶段完成时记录命令、版本、测试数据位置、观察结果、失败与未测范围。只有五项均通过，才称为单节点闭环；遇到不支持或权限无法保证的入口，明确列为阻塞或限制。

## 后续，不并入本次五项验收

- 扩展为 Root → A → A1 三个独立普通 Session，释放 Root 后 A1 继续请求并在重启后恢复。
- 固定版本授权上下文包、父节点离线待审成果、接受/拒绝和兄弟私有历史隔离。
- 多层树与画布共享模型，移动/循环检测、并发 CAS、崩溃恢复。
- 旧数据复制迁移演练：备份、schema 与 ID 映射、幂等、失败恢复及回滚；真实迁移需讨论。
- 附件上传、更多工具、权限策略在插件卸载后的宿主强制，以及目标 OS 的实际安全边界。
